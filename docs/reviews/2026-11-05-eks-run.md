# First EKS run — 2026-11-05

The first apply of the three stacks in AWS (dev account, us-east-1), with the
mesh, loadgen, Chaos Mesh, observability with Mimir and the Argus engine, as
estimated in `docs/cost/2026-10-20-argus-run-estimate.md` (I03). Applied by
hand from an operator's machine, tested, destroyed the same way, and checked
empty. CI did not apply anything (the kill switch stayed on).

About 2 h 10 min of billed time; at the estimate's ≈ $0.62/hr plus usage that
is ≈ $1.50–2.50 (not yet confirmed against the bill).

## Before the apply: the account was not empty

The retired root layout had been applied before (ADR 028 said it had not;
it now carries a correction). The state bucket held `dev/` and `main/` root
states, and the account still had their bootstrap resources: the GitHub OIDC
provider (trusted only by `cloudops-github-actions`), the github-actions and
deployer roles, the state KMS key and the ECR pull-through cache rule. A
foundation apply would have failed on them, and importing them would have
let the destroy delete what CI and the old states use. The run left them
alone (`enable_bootstrap = false`); taking them into the stack is I04.

Also found and, with approval, removed: two empty Route 53 zones for the
domain (both NS and SOA only; the domain is delegated elsewhere) and a log
group from an earlier cluster.

## Defects the run found

Each is fixed in its own PR with a test that fails without the fix, except
where noted.

| Where | Defect |
|---|---|
| foundation | Collided with the existing bootstrap (EntityAlreadyExists) |
| foundation | The state bucket's name output was null without bootstrap, and `terraform_remote_state` drops null outputs: the platform plan failed on the missing attribute |
| mesh images | pricing and ledger built with `golang:1.22` against a go.mod needing 1.26.2 |
| platform | PrometheusRules as `kubernetes_manifest` cannot be planned before kube-prometheus-stack installs their CRD |
| platform | Observability required ingress, because it always created ALB ingresses |
| Loki | Schema v12 refused with structured metadata on; retention without a delete-request store; a 9.8 GiB chunk cache that never scheduled |
| Mimir | Ruler and Alertmanager on the blocks bucket's prefix |
| collector | No `health_check` extension (the chart refuses to install); the deprecated loki exporter's `labels` rejected by 0.104; a batch max below the batch size |
| Grafana | The service-account step waited six minutes for a public URL that exists only with ingress |
| mesh | 64 MiB default limit OOM-killed the Node loadgen API |
| observability | The application namespace stripped chaos-mesh's annotation on every apply (verified by a clean re-plan, no unit test) |
| observability | `mimir_url` named a Service the chart does not create |
| logs | The mesh's stdout never reached Loki (pricing, ledger and inventory had no logs); now an otel-agent DaemonSet, tested on kind, not yet on EKS |

The collector's config is now also checked with `otelcol-contrib validate`
before an apply; it caught the batch defect, which a plan cannot see.

## What was tested

- Orders: placed through the gateway end to end, every hop 200, ledger entry
  ids returned (the internal HMAC key works).
- Telemetry: Mimir had the gateway's `http_server_request_duration_seconds_*`
  with `http_response_status_code`; Tempo had traces from all eight services.
- Argus in the cluster: scored the eight services (fleet 96.7, 22 findings,
  all `sampled`); `argus cost` and `argus backtest` ran against the backends.
- Bench: Argus's four CloudOps scenarios ran the full lifecycle with a stub
  agent; each gate fired on its fault and cleared after (Argus B-62).

## Teardown

The Destroy workflow's steps, run locally: platform destroy (it timed out
once on the monitoring namespace's finalizers and finished on a re-run), the
charts' 11 leftover volume claims deleted and their EBS volumes confirmed
gone, no load balancers, cluster and foundation destroyed, the EKS log group
deleted, one secret in its recovery window force-deleted.

Checked empty afterwards: EKS, EC2, NAT gateways, EIPs, EBS, VPCs and
endpoints, load balancers, Lambda, SQS, EventBridge buses, secrets, log
groups, hosted zones. Left on purpose: the state bucket and old root states,
the bootstrap resources, the cached ECR repository, and two KMS keys (the
current state key and a March one that still encrypts 30 old versions of
`dev/terraform.tfstate`).
