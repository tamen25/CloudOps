# CloudOps

**Production-grade AWS platform engineering on EKS — self-healing operations, multi-window SLO alerting, zero-trust security, and FinOps observability, all provisioned as code and delivered through a gated CI/CD pipeline with no long-lived credentials.**

The platform runs across two availability zones (`us-east-1a`, `us-east-1b`) behind a single Application Load Balancer. All application and infrastructure traffic flows through private subnets; the ALB is the only public-facing entry point. EKS worker nodes live in private subnets and reach the internet through NAT Gateways.

## What This Demonstrates

- **Infrastructure as Code at scale** — 10+ Terraform modules with toggle-based progressive deployment, remote S3 state with native locking (Terraform 1.11+), and a `destroy_all` safety gate
- **Kubernetes production patterns** — IRSA (fine-grained pod-level IAM), OPA Gatekeeper admission control, Falco eBPF runtime threat detection, kube-bench CIS benchmarking, NetworkPolicy enforcement
- **SRE SLO engineering** — multi-window burn rate alerting (1h/6h) for 99.9% availability and p95 < 300ms latency; Lambda-backed error budget tracker writing 30-day history to DynamoDB
- **Self-healing systems** — CloudWatch Alarm → SNS → Lambda controller that safely rolls back deployments, scales out pods, and replaces nodes with blast-radius constraints and dry-run mode
- **Security automation** — compliance scanner Lambda scanning 5 AWS service categories every 6 hours, auto-remediating HIGH/CRITICAL findings and opening GitHub issues for out-of-scope actions
- **FinOps observability** — Cost Explorer ingestion Lambda, AWS Budgets alerts at 80% and 100% of monthly target, idle resource detection, Infracost cost-diff on every PR
- **Zero-credential CI/CD** — GitHub Actions OIDC (no long-lived secrets), 4 workflows: app pipeline with Trivy image scan + automatic rollback, infra pipeline with human approval gate, nightly drift detection that auto-opens/closes GitHub issues, double-gated destroy workflow
- **Full-stack observability** — LGTM stack (Loki, Grafana, Tempo, Prometheus) on EKS, OTel Collector as telemetry gateway, 8 Grafana dashboards auto-provisioned via ConfigMaps, 25-panel operations homepage designed for wall monitors

## Quick Start

Terraform is split into three stacks with their own state, applied in order
(ADR 011, ADR 028): `stacks/foundation` (bootstrap, DNS, networking, database,
compliance), `stacks/cluster` (EKS) and `stacks/platform` (everything on the
cluster). `scripts/terraform-stacks.sh` runs a command across them; the full
walk-through is `docs/runbooks/layered-stack-bringup.md`.

```bash
# 1. Clone and configure
git clone https://github.com/your-org/your-repo.git && cd CloudOps
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars: set project_name, environment, owner, aws_account_id,
# bootstrap_bucket_name

# 2. Create the state bucket (once)
bash modules/bootstrap/create-s3-bucket.sh

# 3. Apply the three stacks: foundation, cluster, platform
bash scripts/terraform-stacks.sh apply

# 4. Configure GitHub secrets (see CI/CD Setup below), then push to trigger
#    pipelines; the app pipeline builds and deploys order-api on push to main
```

Tear down with the Destroy workflow, or `scripts/terraform-stacks.sh destroy`
(`docs/runbooks/demo-teardown.md`).

> **RDS creation takes 5–10 minutes.** This is normal — do not interrupt.

## CI/CD Setup

All four workflows authenticate to AWS via **GitHub Actions OIDC** — no long-lived credentials are stored as secrets.

### Step 1 — Bootstrap (run locally once)

```bash
bash modules/bootstrap/create-s3-bucket.sh
STACK=foundation bash scripts/tf-init.sh
terraform -chdir=stacks/foundation apply -var-file=../../terraform.tfvars -target=module.bootstrap
terraform -chdir=stacks/foundation output -raw github_actions_role_arn  # copy this value
```

### Step 2 — GitHub Secrets

**Settings → Secrets and variables → Actions → New repository secret:**

| Secret | Value |
|--------|-------|
| `AWS_GITHUB_ACTIONS_ROLE_ARN` | `terraform -chdir=stacks/foundation output -raw github_actions_role_arn` |
| `AWS_REGION` | `us-east-1` (or your region) |
| `TF_VARS` | Full contents of `terraform.tfvars` |
| `INFRACOST_API_KEY` | From [infracost.io](https://www.infracost.io/docs/#2-get-api-key) |
| `EKS_CLUSTER_NAME` | `terraform -chdir=stacks/cluster output -raw cluster_name` (EKS Emergency Access only) |
| `GRAFANA_API_KEY` | Grafana → Administration → Service accounts → New token |
| `ORDER_API_KEY_SECRET_ARN` | The order-api API key secret the integration tests sign in with |

The pipelines read the ECR repositories and the cluster name from the stacks'
outputs, so there is no secret to keep in step with them.

### Step 3 — `production` GitHub Environment

**Settings → Environments → New environment → `production`:**
- Enable **Required reviewers** and add yourself
- This gate protects `terraform apply` and the destroy workflow

### Step 4 — Branch Protection on `main`

Required status checks: `quality`, `plan` — blocks merges if Terraform fmt/validate/lint/tfsec/plan fails.

### Workflows

| Workflow | Trigger | What It Does |
|----------|---------|-------------|
| **App Pipeline** (`app.yml`) | Push to `main` on `apps/order-api/**` (gated) · PR · `workflow_dispatch` | Unit tests → Docker build+push to ECR → Trivy image scan → EKS rollout → integration tests (health, orders, metrics, traces) → auto-rollback on failure |
| **Infra Pipeline** (`infra.yml`) | Push to `main` on `*.tf`, `modules/**` (gated) · PR · `workflow_dispatch` | fmt/validate/lint/tfsec, Trivy and Checkov → Infracost cost diff (PR, when `INFRACOST_ENABLED`) → on `main` with `AWS_DEPLOY_ENABLED`: `terraform plan` → manual approval → staged `terraform apply` |
| **Storefront Pipeline** (`storefront.yml`) | Push to `main` on `apps/storefront/**` (gated) · PR · `workflow_dispatch` | lint, contract check, tests with coverage, audit, build, manifest validation → with `AWS_DEPLOY_ENABLED`: build, sign and push to ECR → Trivy image scan → render from Terraform outputs → EKS rollout |
| **Mesh Pipeline** (`mesh.yml`) | Push to `main` on the mesh apps (gated) · PR · `workflow_dispatch` | per-language lint, tests with coverage gates, build, audit; manifest validation → with `AWS_DEPLOY_ENABLED`: each service image built, pushed to ECR, Trivy-scanned (`image-build.yml`), `mesh_*_image` lines printed for the platform tfvars |
| **Loadgen Pipeline** (`loadgen.yml`) | Push to `main` on `apps/loadgen/**` (gated) · PR · `workflow_dispatch` | lint, tests, build → push with `AWS_DEPLOY_ENABLED`: image to ECR. Dispatch: a load run in the cluster (scenario, rps, duration), cloned from the trickle CronJob |
| **Library Pipeline** (`libraries.yml`) | Push to `main` on `libraries/**` (gated) · PR · `workflow_dispatch` | per-language tests + coverage gates → optional publish to CodeArtifact |
| **Destroy** (`destroy.yml`) | `workflow_dispatch` only | Double-gated: `production` env approval + typed confirmation `destroy-everything` → empty the project's buckets → open the cluster API to the runner → destroy platform, the cluster's load balancers, cluster, foundation → state bucket |
| **Drift Detection** (`drift-detection.yml`) | Nightly 02:00 UTC (with `AWS_DEPLOY_ENABLED`) · `workflow_dispatch` | per environment and stack: `terraform plan -detailed-exitcode` with that environment's tfvars → opens a GitHub issue listing the changed resources, closes it when resolved; environments without tfvars are skipped |
| **EKS Emergency Access** (`eks-emergency-access.yml`) | `workflow_dispatch` only | Break-glass: widens the EKS endpoint to a single CIDR via the AWS API in dev, staging or prod, or closes it (state unchanged) |
| **Runner Image** (`runner-image.yml`) | Push to `main` on `ci/runner/**` (gated) · PR · `workflow_dispatch` | PR: build only → with `AWS_DEPLOY_ENABLED`: push the in-VPC runner image to ECR → Trivy scan → prints the digest for `ci_runner_image` |
| **Workflow Lint** (`workflow-lint.yml`) | Any change under `.github/workflows/` | actionlint, then `scripts/check-workflows.py`: OIDC permissions, Terraform wrapper off, kubeconfig before kubectl, no inputs pasted into scripts, plans with tfvars |

#### Toggle: auto-run on merge to `main`

`app.yml`, `infra.yml`, `libraries.yml` only fire on push-to-`main` when the
repository variable `AUTO_RUN_ON_MERGE` is set to `"true"`. Pull requests and
`workflow_dispatch` always fire regardless.

```bash
gh variable set AUTO_RUN_ON_MERGE --body true     # enable auto-run on merge
gh variable delete AUTO_RUN_ON_MERGE              # disable (default)
gh variable list                                   # check current value
```

UI path: Settings → Secrets and variables → Actions → Variables tab.

When disabled, the entry jobs (`quality` in infra, `test` in app, the six
`*-check` jobs + `publish-plan` in libraries) skip on push, and every
downstream job cascade-skips through `needs:`. PR runs and manual dispatches
are unaffected. This lets every promotion to dev/staging/prod be deliberate.

#### Toggle: in-VPC runners for cluster jobs

With a private EKS endpoint, GitHub-hosted runners cannot reach the cluster.
The jobs that need it (app and storefront `deploy`, infra `plan` and `apply`,
`detect-drift`) run on `${{ vars.DEPLOY_RUNNER || 'ubuntu-latest' }}`. Set
`DEPLOY_RUNNER` to `cloudops-vpc` once the ARC runners are up
(`enable_ci_runner`, [docs/runbooks/ci-runner.md](docs/runbooks/ci-runner.md));
unset, everything runs on GitHub-hosted runners.

## Resume Talking Points

- Architected a **self-healing Kubernetes platform on AWS EKS** using Terraform; implemented CloudWatch Alarm → SNS → Lambda controllers that automatically roll back failed deployments, scale out under-replicated pods, and replace unhealthy nodes — eliminating manual intervention for the three most common production failure modes
- Engineered **multi-window SLO burn rate alerting** (1h fast-burn at 14.4×, 6h slow-burn at 6×) for 99.9% availability and 95th-percentile latency targets; built a Lambda-backed error budget tracker persisting 30-day snapshots to DynamoDB and surfacing budget burn in a Grafana dashboard with drill-down to incident history
- Built a **zero-trust security stack on Kubernetes** — Falco eBPF runtime threat detection, OPA Gatekeeper admission control with 5 constraint templates (image registry enforcement, privilege escalation blocking, host path restrictions), daily kube-bench CIS benchmarking, and a compliance scanner Lambda scanning S3/RDS/EKS/IAM/security-groups every 6 hours; auto-remediates HIGH/CRITICAL findings and creates GitHub issues for out-of-scope actions
- Delivered **zero-credential CI/CD** via 4 GitHub Actions workflows authenticated exclusively through OIDC: app pipeline with Trivy image scanning and automatic rollback on integration test failure, infra pipeline with tfsec + Infracost cost-diff + mandatory human approval gate, nightly drift detection that auto-opens and closes GitHub issues on Terraform delta, and a double-gated destroy workflow requiring both environment approval and a typed confirmation
- Implemented **full-stack FinOps and observability**: AWS Cost Explorer ingestion Lambda publishing daily cost metrics to CloudWatch against a $50/month budget (alerts at 80%/100%), idle resource detection across EKS nodes and RDS, LGTM observability stack (Loki/Grafana/Tempo/Prometheus + OTel Collector) with 8 auto-provisioned Grafana dashboards including a 25-panel operations homepage designed for wall-monitor display
